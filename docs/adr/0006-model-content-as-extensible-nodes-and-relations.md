# Model content as extensible nodes and relations

The knowledge core will not hard-code Book, Chapter, Section, or any other
single hierarchy. It will require only stable identity, provenance, content, and
typed relations around extensible Content Nodes, allowing registered content
forms to produce sequences, trees, graphs, tables, or other structures while
derived Retrieval Segments remain traceable to canonical Native Content. V1
implements this model for Markdown Content Documents only and does not build a
general source-format plugin system.
